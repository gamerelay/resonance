# Benchmark: Rust node vs the Go relay (2026-09-29)

The v0 parity gate (GameRelay's Resonance spec, step 3): the Rust node replaces the Go relay only
if it is at least as good under load. **It is, by a wide margin, at every load measured.**

## Setup

- **Relays:** `resonance-node` at `0f8cefd` against gamerelay.io's `deploy/turn` (Go, pion/turn
  v4.1.4), both release builds for linux/arm64 with the same limits and config
  (`TURN_SECRET`, `TURN_PUBLIC_IP=127.0.0.1`, relay ports 40000–59999).
- **Load:** `interop/cmd/bench`. Pairs of pion TURN clients (the same client code for both
  relays): each pair is one room, each player from its own loopback address. They allocate, the
  first writes create permissions and channels, and after a 3 s warm-up each player sends 60
  packets a second of 200 bytes to the other (a game-like rate), for 10 s. Each packet carries its
  send time; the receiver takes the one-way latency.
- **Where:** a Docker Linux VM on an Apple M5 Max (18 CPUs), loopback. The load generator shares
  the machine with the relay, so tail latency at the highest loads includes its own scheduling.
  Both relays see the same generator. Socket buffers were the container's default (the kernel caps
  them at 208 KB there; `install.sh` raises them on real hosts).
- Each point was run twice, alternating which relay ran first. Below: the two runs' mean.

## Results

| Pairs (allocations) | Packets/s | Relay | p50 | p99 | p99.9 | Loss | CPU | Memory per allocation |
|---|---|---|---|---|---|---|---|---|
| 50 (100) | 6,000 | Go | 1.09 ms | 3.15 ms | 6.64 ms | 0 | 16% | 23.7 KB |
| | | **Rust** | **0.22 ms** | **1.22 ms** | **2.30 ms** | 0.03% | **2.8%** | **1.6 KB** |
| 200 (400) | 24,000 | Go | 2.62 ms | 7.18 ms | 9.52 ms | 0 | 43% | 19.7 KB |
| | | **Rust** | **0.23 ms** | **1.86 ms** | **3.83 ms** | 0.03% | **9.6%** | **0.9 KB** |
| 1,000 (2,000) | 120,000 | Go | 2.25 ms | 10.5 ms | 15.8 ms | 0.02% | 136% | 14.9 KB |
| | | **Rust** | **0.18 ms** | **2.66 ms** | **7.40 ms** | 0.005% | **27%** | **0.8 KB** |
| 2,000 (4,000) | 236,000 | Go | 30.8 ms | 99.2 ms | 255 ms | **7.9%** | 284% | 14.7 KB |
| | | **Rust** | **0.27 ms** | **9.87 ms** | **36.2 ms** | 0.005% | **48%** | **0.7 KB** |

- **Median latency stays flat, about 0.2 ms at every load**, where the Go relay's grows from 1 ms
  to 31 ms. At 2,000 pairs the Go relay also drops 8% of packets; the Rust node drops almost
  none.
- **CPU: about a fifth.** The Rust node is one thread: at 240,000 packets a second it uses half a
  core, so one core carries about twice that. The Go relay spreads over cores and still uses six
  times as much.
- **Memory: 15–20 times less per allocation.** Relay addresses are names, not sockets.
- **Binary:** 386 KB (5.3 MB for Go).

What these numbers don't show: a real network's latency (tens of ms) swamps the relay's own in
production; the point is that the relay adds almost nothing, keeps its tail short under load,
and a $6 one-core VPS has room for many thousands of players.

## Open

- **Rust's small loss at low load** (0.02–0.05% at 50–200 pairs, none at 1,000+) isn't
  explained yet. The likeliest cause is the 208 KB receive buffer overflowing in bursts, since
  every client's traffic lands on the node's one socket. To check on a real host with 4 MB
  buffers.
- **A host-level check on the SF relay** (the spec's step 3): run the same load against both
  relays on the production box before swapping.

## Reproduce

```sh
# Build both relays and the bench tool for Linux, then run in a Linux container:
(cd interop && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o /tmp/b/relay-bench ./cmd/bench)
(cd ../gamerelay.io/deploy/turn && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -o /tmp/b/go-relay .)
docker run --rm -v "$PWD":/src -v /tmp/b:/out -e CARGO_TARGET_DIR=/out/t -w /src rust:1 \
  sh -c 'cargo build --release -p resonance-node && cp /out/t/release/resonance-node /out/rust-relay'
docker run --rm -v /tmp/b:/b -w /b --ulimit nofile=65536:65536 rust:1 \
  ./relay-bench -name rust -relay ./rust-relay -pairs 1000 -duration 10s -spread
```
